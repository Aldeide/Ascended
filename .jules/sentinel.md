## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.

## 2026-10-13 - [Fix Authorization Bypass in Network RPCs]
**Vulnerability:** Found `[Rpc(SendTo.Server)]` Server RPCs in `AbilitySystemComponent.cs` and `EquipmentComponent.cs` that lacked the `RequireOwnership = true` parameter, and ability termination logic in `ReplicationManager.cs` that didn't validate if a client had the appropriate network policy authority to terminate the ability (e.g., terminating ServerOnly abilities).
**Learning:** Unity Netcode for GameObjects Server RPCs need explicit ownership requirements to prevent any connected client from executing operations on objects they don't own. The framework delegates logic to `ReplicationManager`s, but the security check is needed in BOTH the entry point (ownership validation on the RPC) and inside the specific business logic (validating ability network policies).
**Prevention:** Always add `RequireOwnership = true` to `[Rpc(SendTo.Server)]` when standard component behavior dictates only the local player should perform an action. For server-authoritative components (like abilities), enforce checks (like `HasAuthorityToTerminate`) inside replication manager handlers before delegating to internal managers.
