## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.
## 2026-10-06 - Authorization Bypass in Ability Termination
**Vulnerability:** A missing client authorization check in `ProcessServerAbilityTermination` within `ReplicationManager` allowed any client to arbitrarily terminate active abilities (even server-authoritative ones) on the server, bypassing `NetworkSecurityPolicy` restrictions by sending unverified RPC requests.
**Learning:** Unity Netcode Server RPCs act as raw ingestion points. While ability activation properly delegated to a dedicated validation check (`ProcessServerAbilityActivation` checking `HasAuthorityToActivate`), termination logic skipped this validation entirely and immediately executed the state change (`EndAbility`). Validation logic must be explicitly mirroring the activation flow.
**Prevention:** Always explicitly validate both activation AND termination requests via centralized authorization checks (`HasAuthorityToTerminate`) before modifying server-authoritative state via RPCs.
