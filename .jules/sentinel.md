## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.

## 2026-10-10 - Fix client authorization bypass on server ability termination
**Vulnerability:** A malicious or compromised client could terminate ANY ability (even server-only ones) by sending an end ability RPC.
**Learning:** `ProcessServerAbilityTermination` and `ProcessServerAbilityBatch` within `ReplicationManager` and `MockReplicationManager` were delegating termination directly to `AbilityManager.EndAbility(string abilityName)`. However, `EndAbility` relies on checking `_owner.IsServer()`, which incorrectly evaluated to `true` on the server even when processing an RPC request originating from a client. This allowed client-initiated requests to bypass the `HasAuthorityToTerminate` authorization checks designed for clients.
**Prevention:** Always explicitly validate client authorization using `AbilityManager.HasAuthorityToTerminate(ability, isClient: true)` within the RPC handler BEFORE delegating execution to an internal manager method that incorrectly infers context (e.g., assuming server authority just because the method is running on the server).
