## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.

## 2026-10-11 - RPC Client Authority Bypass
**Vulnerability:** The `ReplicationManager` handled server-side termination requests (e.g., `ProcessServerAbilityTermination`) by directly calling `AbilityManager.EndAbility(name)`. Inside `EndAbility`, because the method was executing on the server, the internal check `_owner.IsServer()` was true, which caused the internal client authority checks to be skipped. This allowed malicious clients to forge termination RPCs and bypass the `NetworkSecurityPolicy`, ending server-only abilities prematurely.
**Learning:** Security and authority checks (like `HasAuthorityToTerminate`) meant for clients must be explicitly invoked *before* passing client-initiated RPC payloads to shared server logic that assumes full authority based on its execution context.
**Prevention:** Always validate client authorization against defined security policies (e.g., `NetworkSecurityPolicy`) at the network layer entry point (`ReplicationManager`) when handling client RPCs, using explicit named arguments (e.g., `isClient: true`) to clarify intent and avoid logic bugs.
