## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.
## 2026-11-02 - Authorization Bypass in Unity Netcode RPCs
**Vulnerability:** Connected clients could execute server RPCs for NetworkObjects they do not own by exploiting the default behavior of `[Rpc(SendTo.Server)]`, and server-side delegations incorrectly assumed server authority when evaluating client actions.
**Learning:** In Unity Netcode for GameObjects, the `[Rpc]` attribute does not enforce ownership by default (unlike `[ServerRpc]`). Additionally, server-side delegations checking authorization using a boolean flag like `HasAuthorityToActivate(ability, true)` are prone to automated review rejection due to ambiguity over what `true` means.
**Prevention:** Explicitly enforce ownership on server RPCs using `[Rpc(SendTo.Server, RequireOwnership = true)]`. For server-side delegations checking client authority, use C# named arguments for boolean parameters (e.g., `isClient: true`) to clarify intent and prevent automated rejections.
