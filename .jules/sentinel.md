## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.
## 2024-05-24 - [HIGH] UI Rich Text Injection in Lobby List
**Vulnerability:** Unsanitized Steam host names were being displayed directly in the Lobby UI using UI Toolkit labels (`label.text = $"{lobby.GetData("HostName")}'s Lobby..."`). This allows a malicious user with HTML-like tags in their Steam name (e.g., `<color=red>`) to perform UI Rich Text Injection.
**Learning:** Even though `NetworkLobbyState.UpdatePlayerNameServerRpc` correctly sanitizes names for players *in* the lobby using `FixedString64Bytes`, the lobby browser itself (`MainMenuUI`) relies on the raw `HostName` metadata provided by Steam matchmaking, which bypasses the Netcode sanitization entirely.
**Prevention:** Always sanitize untrusted, user-controlled strings (especially names from external services like Steam) using utilities like `StringUtilities.SanitizeForRichText` immediately before assigning them to UI labels or setting them as lobby metadata. I added a `string` overload to `SanitizeForRichText` to make this easier for non-Netcode strings.
