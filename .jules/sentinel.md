## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.
## 2026-10-16 - Missing Server Authorization Checks & RPC Ownership Defaults
**Vulnerability:** `ProcessServerAbilityTermination` in ReplicationManager allowed any client to terminate any ability (authorization bypass). `[Rpc(SendTo.Server)]` in Unity Netcode allowed any connected client to execute RPCs on any object by default without ownership.
**Learning:** Unity Netcode delegates networking logic to Replication Managers. When implementing server-authoritative functionality, both activation and termination paths must explicitly validate client authorization against the defined `NetworkSecurityPolicy` before delegating to internal managers (which may rely on checks like `IsLocalClient()` that incorrectly evaluate to false on the server). Additionally, the newer `[Rpc(SendTo.Server)]` attribute does not require ownership by default, unlike the older `[ServerRpc]`.
**Prevention:** Always explicitly enforce ownership using `[Rpc(SendTo.Server, RequireOwnership = true)]` to prevent authorization bypasses. In Server RPCs within Replication Managers, always include explicit client authorization validation (e.g., `AbilityManager.HasAuthorityToTerminate(ability, isClient: true)`) before modifying server state.
