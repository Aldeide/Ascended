## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.
## 2024-09-18 - Prevent Information Exposure via SendTo.Everyone
**Vulnerability:** Used `[Rpc(SendTo.Everyone)]` combined with client-side ID filtering for transmitting debug data. This meant the payload (sensitive full server debug state) was broadcast to all connected clients, exposing system state despite client-side filtering ignoring the data on the wrong clients.
**Learning:** Client-side filtering in RPCs does not prevent network transmission to unauthorized clients. If an RPC is sent to `SendTo.Everyone`, every client will receive the data packets regardless of whether the receiving method immediately returns.
**Prevention:** Use `[ClientRpc]` (or targeted SendTo attributes depending on NGO version) combined with `ClientRpcParams { Send = new ClientRpcSendParams { TargetClientIds = new[] { targetId } } }` to ensure the data is only ever transmitted to the intended recipient over the network.
