## 2024-05-21 - TextMeshPro Rich Text Injection
**Vulnerability:** A malicious client could send rich text tags (like `<color=red>`) in their `FixedString64Bytes` player name over a `ServerRpc`. TextMeshPro evaluates these tags indiscriminately, leading to UI spoofing or breaking layout for all clients when the lobby state is synced. This is the Unity equivalent of Cross-Site Scripting (XSS).
**Learning:** `FixedString` types in Unity Collections do not have built-in sanitization and are often blindly passed to UI elements.
**Prevention:** Always sanitize player-provided strings using a centralized utility (like `StringUtilities.SanitizeForRichText`) that strips `<` and `>` characters *before* updating authoritative network state via ServerRpc.
## 2026-10-03 - Missing Authorization Check in Server RPC for Ability Termination
**Vulnerability:** The server RPC handler `ProcessServerAbilityTermination` in `ReplicationManager` did not check if the requesting client actually had authorization to terminate the ability based on its `NetworkSecurityPolicy`. Any client could send an RPC to forcefully terminate server-side abilities.
**Learning:** Unity Netcode server RPC methods must explicitly validate client authority even when delegating to internal managers, as internal methods like `EndAbility()` might check `IsLocalClient()` which would incorrectly evaluate to true when called by the server on behalf of a client.
**Prevention:** Always validate client authorization against the defined security policy in server RPC handlers before delegating to internal network-agnostic methods. Use explicit named arguments (e.g., `isClient: true`) for clarity in authorization checks.
